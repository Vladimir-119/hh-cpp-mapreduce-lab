# Анализ вакансий разработчиков C и C++

Лабораторная работа по дисциплине «Инженерия данных».

**Автор:** Волков Владимир.  
**Вариант 6:** «Программист, разработчик на C и C++».

Проект загружает данные вакансий в RustFS, рассчитывает частоты навыков, пар и троек собственным MapReduce и независимыми SQL-запросами DuckDB, затем проверяет полное совпадение результатов. Дополнительно выполнены профилирование времени и памяти, проверка повтора задачи маппера, анализ зарплат и сравнение трёх регионов.

**Отчёт:** [Volkov_C_CPP_MapReduce_report.pdf](Volkov_C_CPP_MapReduce_report.pdf).

## Данные

Источник: [IT Vacancies from HeadHunter Website](https://www.kaggle.com/datasets/ilyazawilsiv/it-vacancies-from-headhunter-website), Kaggle, автор ilyazawilsiv. Период публикации вакансий: 18.09.2023–17.10.2023.

В `data/hh_it_vacancies.csv` сохранены необходимые столбцы всех 68 770 исходных вакансий. Происхождение данных, список столбцов и хеши приведены в [data/provenance.json](data/provenance.json).

Команда `prepare` преобразует CSV в JSONL без отбора варианта. Навыки берутся из `key_skills`, из описаний они не извлекаются. Пропуски зарплат не заполняются. MapReduce и DuckDB затем самостоятельно отбирают вакансии из одного полного объекта в S3.

## Требования

- Python 3.12 или новее.
- uv.
- Docker с Docker Compose.
- Доступ к интернету при установке зависимостей, загрузке образа RustFS и расширения DuckDB `httpfs`.

Все команды выполняются из корня репозитория.

## Запуск

### 1. Установка и настройка

```bash
uv sync --frozen --no-dev
cp .env.example .env
```

Параметры задаются в `.env`:

| Переменная | Назначение | Значение в шаблоне |
|---|---|---|
| `S3_ENDPOINT` | Адрес S3 API | `http://127.0.0.1:9000` |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Ключи доступа RustFS | Заменить заглушки своими значениями |
| `S3_REGION` | Регион S3 | `us-east-1` |
| `S3_BUCKET` | Бакет | `hh-lake` |
| `S3_KEY` | Ключ входного объекта | `raw/it_vacancies.jsonl` |
| `WORKERS` | Процессы MapReduce и потоки DuckDB | `2` |
| `CHUNK_ROWS` | Строк в чанке MapReduce | `500` |
| `MIN_SALARY_N` | Минимум зарплат для рейтинга сочетаний | `5` |
| `REGIONS` | Города для сравнения | Москва, Санкт-Петербург, Новосибирск |

В `REGIONS` названия городов разделяются символом `|`.

### 2. Запуск RustFS

```bash
docker compose --env-file .env -f infra/docker-compose.yml up -d
docker compose --env-file .env -f infra/docker-compose.yml ps
```

S3 API доступен на `http://127.0.0.1:9000`, веб-консоль — на `http://127.0.0.1:9001`. Ключи доступа контейнера берутся из `.env`.

Используются четыре каталога `infra/disks/disk1`–`disk4`, смонтированные в `/data1`–`/data4`. Для локального развёртывания на одном физическом диске включён `RUSTFS_UNSAFE_BYPASS_DISK_CHECK`.

### 3. Подготовка и загрузка данных

```bash
uv run --frozen --no-dev python lab.py prepare
uv run --frozen --no-dev python lab.py upload
```

`prepare` создаёт `data/it_vacancies.jsonl`. Контрольные значения:

```text
Строк: 68770
Размер: 30732626 байт
SHA-256: d9bb991e4932c95d2231decb70f21b31338c4be0a3b89cf9d1a8cbfefd20e2b5
```

`upload` создаёт бакет при необходимости, загружает объект и сохраняет протокол в `evidence/storage.json`.

### 4. Расчёты, верификация и профилирование

```bash
uv run --frozen --no-dev python lab.py setup-duckdb
uv run --frozen --no-dev python lab.py benchmark --repeats 3
```

Первая команда устанавливает и загружает `httpfs`. Вторая выполняет девять запусков: по три для наивного MapReduce, MapReduce с combiner и DuckDB. Методы чередуются, каждая попытка запускается в отдельном процессе.

Для каждой попытки измеряются время и пик памяти, сохраняются частоты и проверяется совпадение с эталонным запуском. Ожидаемое сообщение:

```text
full equality OK
```

Локальные результаты находятся в `results/<имя запуска>/`. В RustFS сохраняются `results/<имя запуска>/counts_k1.csv`, `counts_k2.csv`, `counts_k3.csv` и `summary.json`.

### 5. Проверка сбоя маппера

```bash
uv run --frozen --no-dev python lab.py failure-test
```

Для чанка 0 искусственно вызывается исключение после map, до добавления результата в reducer. Чанк повторяется один раз и учитывается только после успешного завершения. Полные частоты сравниваются с успешным запуском без сбоя.

Ожидаемый итог:

```text
Mapper failure, retry and full equality: OK
```

Протокол — `evidence/mapper_failure.json`, журнал — `results/failure-*/stdout.log`. Проверяется сбой задачи, а не аварийное завершение процесса или сервера.

### 6. Анализ зарплат и регионов

```bash
uv run --frozen --no-dev python lab.py analyze
```

Команда создаёт:

- `results/salary_effects.csv` — частоты, медианы и различия зарплат для пар и троек относительно базы.
- `results/regions_summary.csv` — число вакансий и зарплатные показатели по городам.
- `results/regions_skills.csv` — топ-5 навыков, пар и троек в каждом городе.
- `results/analysis.json` — подробные результаты, включая состав зарплатных подвыборок.

## Как работает расчёт

### Отбор варианта

Вакансия должна иметь `professional_roles_id = 96` и явное упоминание C или C++ в названии. Учтены кириллическая «С», обозначение «Си» и `c developer`. Исключаются ложные совпадения с 1С, C#, Objective-C и инициалами. Общие названия без указания языка могут не попасть в выборку.

Python-условие находится в `source_tools.is_variant`, независимое SQL-условие — в [sql/variant.sql](sql/variant.sql). SQL не вызывает Python-фильтр и не использует заранее рассчитанный признак варианта.

### Навыки и сочетания

Названия навыков приводятся к нижнему регистру, пробелы по краям и повторы внутри вакансии удаляются, список сортируется. Разные исходные теги, например `c++` и `c/c++`, сохраняются отдельно. Частота сочетания — число вакансий, в которых оно встречается.

Вакансия с `m` навыками даёт `m` одиночных вхождений, `m(m−1)/2` пар и `m(m−1)(m−2)/6` троек. Например, при 10 навыках это 10, 45 и 120 сочетаний. Суммы этих вкладов проверяются программой.

### MapReduce

`chunks_from_s3` получает объект через `boto3.get_object`, читает `StreamingBody.iter_lines` с буфером 64 KiB и формирует чанки по `CHUNK_ROWS` строк. Мапперы работают в отдельных процессах. Число незавершённых задач ограничено значением `2 × WORKERS`.

Маппер отбирает вакансии и строит сочетания через `itertools.combinations`. Наивный вариант передаёт каждое вхождение отдельно, оптимизированный предварительно агрегирует одинаковые ключи через `Counter` — локальный combiner. Reducer суммирует результаты успешных задач.

### DuckDB и проверка совпадения

DuckDB читает `s3://hh-lake/raw/it_vacancies.jsonl` через `httpfs`. Запрос [sql/counts.sql](sql/counts.sql) разворачивает навыки в строки, строит пары и тройки по позициям `i < j < k` и считает частоты через `GROUP BY`.

Сравниваются все ключи и частоты для `k = 1, 2, 3`, число выбранных вакансий, хеш списка ID и распределение размеров стеков. Проверка не ограничивается сравнением итоговых сумм.

### Зарплаты и регионы

В медианы включаются положительные зарплаты в рублях с `salary_gross = false`. Для двух корректных границ берётся середина вилки, для одной — указанная граница. Пропуски, другие валюты, зарплаты до налогов и некорректные вилки исключаются.

База пары — более частый отдельный навык, база тройки — самая частая составляющая пара. Частоты базы определяются по всем вакансиям варианта; при равенстве используется лексикографический порядок. База включает вакансии с добавленным навыком. В рейтинг входят сочетания минимум с `MIN_SALARY_N` зарплатами. Для троек также сохраняются показатели самого частого одиночного навыка.

Региональные доли рассчитываются от всех вакансий варианта в городе, включая вакансии без навыков. Для Москвы, Санкт-Петербурга и Новосибирска показаны частоты навыков, пар и троек, число зарплат и медианы. Разницы зарплат описывают связь с составом вакансий и не устанавливают причинный эффект навыка или региона.

## Результаты экспериментов

Запуски выполнены 21 октября 2026 года на macOS 15.8.1, arm64, Python 3.12.14. Использованы два процесса/потока и чанки по 500 строк.

| Показатель | Значение |
|---|---:|
| Строк во входном объекте | 68 770 |
| Вакансий варианта | 869 |
| Вакансий с навыками | 676 |
| Различных навыков / сумма частот | 747 / 3 833 |
| Различных пар / сумма частот | 6 800 / 13 468 |
| Различных троек / сумма частот | 31 306 / 43 504 |

Во всех девяти запусках полные результаты совпали. После повтора задачи маппера совпадение сохранилось.

| Метод | Медиана времени, с | Медиана пика RSS, MiB |
|---|---:|---:|
| Наивный MapReduce | 0.889 | 172.3 |
| MapReduce с combiner | 0.854 | 172.1 |
| DuckDB | 0.706 | 289.3 |

Время включает запуск Python, S3 HEAD/GET, расчёты, сортировку, локальную запись и загрузку результатов в S3. Пик памяти — максимальная наблюдаемая сумма RSS процесса и его живых потомков при опросе каждые 10 мс. Память RustFS не учитывается; общие страницы процессов могут учитываться повторно, короткие пики могут быть пропущены. Холодный кэш не обеспечивался.

Combiner снизил медиану времени примерно на 3,9%, медиану пика памяти — примерно на 0,1%. DuckDB показал меньшую медиану времени при большем потреблении памяти. Точные измерения всех попыток и параметры среды находятся в [results/benchmark.json](results/benchmark.json); интерпретация приведена в отчёте.

## Тесты

```bash
uv sync --frozen
uv run --frozen pytest -q
```

В `tests/test_correctness.py` проверяются частоты на контрольных примерах, пограничные случаи отбора C/C++-вакансий, совпадение Python и SQL на полном подготовленном JSONL, правила обработки зарплат и учёт вакансий без зарплаты. Для проверки полного набора предварительно выполняется команда `prepare`.
